# ADR 0002：行情连续性恢复与实时 Bar 单调性

状态：Accepted
日期：2026-07-13

## 背景

旧实时轮询只回补日线，并在单个回补异常后继续处理 Tick 且清除恢复标志。分钟聚合还采用自然周期
起点，与 miniQMT 的 5m/15m/30m/1h 周期结束标签不一致。跨日累计量较大、同日累计量回退、旧 Tick
以及闭市后首次快照都可能污染或覆盖已回补的 finalized 历史。

## 决策

1. 启动、watchlist 扩展及任何轮询失败后，将相关标的置为连续性恢复中。
2. 恢复顺序固定为：官方交易日历 → 1m/5m/15m/30m/1h/1d 回补 → 清除旧 provisional 状态
   → 读取新 Tick。任一步失败均保持恢复状态，且 `market_fresh=false`。
3. 分钟 Bar 使用 miniQMT 周期结束标签；1m 历史序列保留 09:30 集合竞价 Bar，连续竞价实时聚合
   从下一分钟标签开始，午后首根为 13:01。
4. 累计成交量和成交额按交易日建立基线。同日回退只记录拒绝事实，不降低基线；旧、未来和非官方
   交易日 Tick 不进入 Bar。
5. 恢复后的首个在途分钟周期不可持久化。只有随后连续观察到的完整周期才能进入 finalized 流水线。
6. 日 Bar 只有在收盘前已被当前进程观察、随后观察到收盘事实时才持久化。闭市后首次快照只用于
   展示，不得覆盖刚回补的官方 finalized Bar。
7. K 线 API 将 backfill、calendar 和 realtime 错误分别返回，并以 `continuity_verified` 区分
   “没有发现缺口”和“已经证明连续”。

## 后果

- 断线和回补失败期间不会用旧快照维持虚假的行情新鲜度。
- 恢复后的首个分钟周期可能只作为 provisional 展示而不落盘；权威历史由下一次 miniQMT 回补补齐。
- 每个恢复标的需要六个周期的增量查询，延迟高于旧日线单周期流程，但状态可审计且不会静默缺失。
- 快照轮询仍不是逐笔成交源；边界附近的低频聚合误差由后续官方历史回补取代。
